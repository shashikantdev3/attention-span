Codex CLI Issue Says It Now Starts a Self-Updating Background Daemon by Default

A GitHub issue on OpenAI’s Codex CLI says version 0.157.0 starts a persistent, self-updating background daemon by default and asks for it to be opt-in.

According to a user’s GitHub issue, since version 0.157.0 opening an interactive Codex session automatically starts a persistent background daemon. It copies the platform package into a local directory and runs from that copy, decoupling the backend version from the installed CLI version. It also launches a detached updater that checks for updates and restarts the backend. Users reported issues where stopping the app-server leaves the updater running, environment variables are pinned to the first session, and the CLI becomes unusable on certain platforms.

Opening the tool is like turning on a background helper that stays awake even after you close the room, and it updates itself without asking you first.

Why it matters

Background daemons that decouple execution identity from the installed client can break environment variables and disrupt standard workflows.
