Opinion: Agent memory formats need a shared standard, like OpenTelemetry

A LoreKit author argues that agent memory formats are fragmented and the community should agree on a shared data model, as observability did with OpenTelemetry.

An article by the maker of the open source tool LoreKit says coding tools store agent memory in formats that cannot read each other, such as AGENTS.md, CLAUDE.md, Cursor rules, a /memories directory and a memory MCP server. It compares this to observability before 2019, when OpenTracing and OpenCensus merged into OpenTelemetry. It lists existing proposals, including Portable Memory, the Open Memory Protocol draft and Cognee's COGX. It says a spec should answer four questions: where a memory is true, its identity, its content, and when it stops being true. It also shows an illustrative record, and says the field names are not a proposal.

Like I am 5

Imagine every kid in class keeps notes in a different kind of notebook, so nobody can read anyone else's. The idea is to all agree on one notebook layout so notes can be shared.

Why it matters

Memory an agent learns in one tool, like a CI agent, stays locked there today, so a shared format would let different tools read and reuse the same notes.
