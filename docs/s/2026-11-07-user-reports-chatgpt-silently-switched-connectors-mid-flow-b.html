User reports ChatGPT silently switched connectors mid-flow; bounty program asks for ID

A forum user reports ChatGPT sent a follow-up tool call through a different connector without telling them, and says the bug bounty required an ID card.

A user on the OpenAI community forum reports that ChatGPT, with two connectors enabled for the same MCP server, made a follow-up tool call through a different connector than the one that started the flow. Connector A showed a widget and produced a one-time confirmation code. The model then sent that code through connector B. The server rejected the call because the code was bound to connector A's OAuth client. The user was not told about the switch. The poster says the expected behavior is matching calls by OAuth client, not server URL. They also say the bounty program required biometric ID and an ID card, so they did not submit.

Imagine you give a note to one friend, but a different friend quietly delivers it without telling you. The note was only meant for the first friend, so the door stays shut.

Why it matters

If a client swaps connectors mid-flow, servers must bind confirmation codes and grants to the OAuth client, because a shared MCP URL does not prove the same app is calling.
