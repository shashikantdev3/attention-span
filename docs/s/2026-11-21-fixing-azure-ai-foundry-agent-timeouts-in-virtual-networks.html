Fixing Azure AI Foundry Agent Timeouts in Virtual Networks

Troubleshoot hosted agent timeouts in custom virtual networks using five checks for subnets, DNS, and traffic.

Moving hosted agents into a custom virtual network can lead to timeouts on the Agents page if the surrounding network setup is missing key pieces. Teams can verify their deployment by performing five specific checks. These checks confirm the correct agent subnet is delegated and sized properly, ensure private endpoints and DNS zones for Azure Cosmos DB and other services are correctly linked, and account for traffic restrictions such as firewall TLS inspection on Microsoft Entra ID sign-ins. Network injection must be configured when creating the Foundry account.
